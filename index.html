Textbook · Section 00

実行の全体フロー
The whole pipeline — 順序を理解する

最重要

コードの実行順を問う形式に備えておく価値があります。個々のメソッド名を覚えていても、「なぜこの順番でなければならないのか」が分かっていないと解けません。逆にここを理解すると、④⑤⑥⑦の問題がまとめて解けるようになります。まずこの流れを頭に入れてください。

# ① サービスに接続する(IBMの量子計算サービスへの窓口を作る)
from qiskit_ibm_runtime import QiskitRuntimeService, SamplerV2 as Sampler
service = QiskitRuntimeService()

# ② 使う量子コンピュータ(バックエンド)を決める
backend = service.least_busy(operational=True, simulator=False)

# ③ 回路を組む(まだ実機のことは考えない、理想的な回路)
qc = QuantumCircuit(2, 2)
qc.h(0); qc.cx(0, 1); qc.measure([0,1], [0,1])

# ④ その実機で動く形に変換する(トランスパイル)
pm  = generate_preset_pass_manager(optimization_level=1, backend=backend)
isa = pm.run(qc)

# ⑤ 道具(プリミティブ)を用意する
sampler = Sampler(mode=backend)

# ⑥ 実行する(PUB のリストを渡す)
job = sampler.run([isa])

# ⑦ 結果を受け取る
result = job.result()
counts = result[0].data.c.get_counts()

流れを図にすると次の通りです:

0-1. なぜこの順番なのか(理由が分かれば並び替え問題は解ける)

順番やることなぜその位置なのか
①QiskitRuntimeService()すべての出発点。バックエンドはサービス経由でしか取得できないので、必ず最初。
②backend を決める次のトランスパイルが「どの実機に合わせるか」を必要とするため、変換より前に決まっていなければならない。
③回路を組む変換される「元の回路」。①②とは独立なので、実は先に書いてもよい。
④トランスパイル実行より前。理想的な回路のままでは実機で動かないため、必ず変換してから渡す。
⑤プリミティブを作る実行の直前。どこで動かすか(backend / session / batch)を mode= で渡す。
⑥run()変換済み回路(ISA回路)を渡して実行。ここで初めてジョブが投入される。
⑦result()実行後にしか結果は存在しない。当然いちばん最後。
💡 並び替え問題は「依存関係」で解く

順番を丸暗記する必要はありません。「その行が必要とするものが、それより前で作られているか」を見れば決まります。

・service.least_busy() は service が要る → service が先
・generate_preset_pass_manager(backend=backend) は backend が要る → backend が先
・pm.run(qc) は pm と qc が要る → 両方が先
・sampler.run([isa]) は sampler と変換済みの isa が要る → 両方が先
・job.result() は job が要る → run が先

この「使う変数は、使う前に作られていなければならない」という当たり前の原則だけで、正しい順番は一意に決まります。

💡 なぜトランスパイルが必要なのか(理解しておくと④が楽になります)

私たちが書く回路は「理想的な量子コンピュータ」向けです。しかし実機には制約があります。

・使えるゲートの種類が決まっている(basis gates)。実機は数種類の基本ゲートしか実行できず、H や CX もそれらの組み合わせに置き換える必要があります。
・qubit の繋がり方が決まっている(coupling map)。隣り合っていない qubit 同士では2量子ビットゲートを直接かけられません。
・無駄を削れる(optimization)。打ち消し合うゲートなどを整理できます。

この「実機の事情に合わせて書き換える」作業がトランスパイルで、変換後の回路を ISA回路(Instruction Set Architecture に沿った回路)と呼びます。プリミティブに渡すのは必ずこのISA回路です。

0-2. Session / Batch を使う場合

複数のジョブをまとめたい場合は、プリミティブを作る前に Session や Batch を開き、それをプリミティブに渡します。

with Session(backend=backend) as session:      # Session/Batch には backend= で実機を渡す
    sampler = Sampler(mode=session)            # プリミティブには mode= で「実行の場」を渡す
    job = sampler.run([isa])
💡 mode= と backend= が別の名前である理由

混同しやすい2つですが、意味を考えると自然に区別できます。

・Session / Batch は「どの実機を予約するか」を決めるもの。だから引数は backend=(実機そのもの)。
・Sampler / Estimator は「どういう文脈で実行するか」を受け取ります。渡せるのは backend 単体でも、Session でも、Batch でもよい。複数の種類を受け取れるので、より広い意味の mode=(実行モード)という名前になっています。

つまり mode= は「実行の場所・文脈」を指す包括的な引数、backend= は「実機」を指す具体的な引数、という関係です。

⚑ ここは最優先で押さえる
実行順を問う形式は、この流れがそのまま骨格になります。service → backend → circuit → transpile → primitive → run → result。迷ったら「この行が使っている変数は、どこで作られたか」を確認してください。

1-1. 量子ビットと状態

1量子ビットは $|0\rangle=\begin{pmatrix}1\\0\end{pmatrix}$、$|1\rangle=\begin{pmatrix}0\\1\end{pmatrix}$ の重ね合わせ $|\psi\rangle=\alpha|0\rangle+\beta|1\rangle$($|\alpha|^2+|\beta|^2=1$)。測定で $|1\rangle$ が出る確率は $|\beta|^2$。Bloch球では極角 $\theta$(Z軸からの傾き)で確率が決まり、$\theta=\pi/2$(赤道)なら $|0\rangle,|1\rangle$ が各50%。

💡 なぜ位相ゲートは |1⟩ にだけ効くのか(頻出の落とし穴)

Z・S・T・P は $\mathrm{diag}(1,\ \cdot)$ の形で、|1⟩ の係数にだけ数をかけ、|0⟩ は1倍で不変。だから $Z|0\rangle=|0\rangle$, $S|0\rangle=|0\rangle$, $T|0\rangle=|0\rangle$(|0⟩を動かせない)。図問題やBell問題で「Zがあるから位相反転?」と誘われるが、Zが |0⟩ 成分にかかっていれば無効。

理由:意味があるのは状態間の相対位相だけ。|0⟩ に位相をかけても全体にかかるグローバル位相になり、$e^{i\phi}|\psi\rangle$ と $|\psi\rangle$ は物理的に同一(測定でも干渉でも観測不能)。だから慣習上 |1⟩ 基準で定義される。

💡 RX / RY / RZ の違い(確率を変えるのはどれ?)

Bloch球で各軸まわりの回転。|0⟩ から始めると:
・RZ=Z軸まわり → |0⟩(北極=軸の真上)は動かず P(1)=0 のまま(位相だけ変える)
・RY=Y軸まわり → 実数のまま倒れる。$P(1)=\sin^2(\theta/2)$、位相が付かず一番素直(計算問題の主役)
・RX=X軸まわり → 倒れるが |1⟩ 側に $-i$ が付く。確率はRYと同じ($|-i|=1$ で消える)

ワナ:「|0⟩ に rz をかけて測定、P(1)は?」→ 0($\sin^2$ を計算させる罠。Z軸は確率を変えない)。

1-3. RYで作る確率(計算問題の定番)

$RY(\theta)|0\rangle=\cos\frac\theta2|0\rangle+\sin\frac\theta2|1\rangle$。よって $|1\rangle$ の確率は $\sin^2(\theta/2)$。

from qiskit import QuantumCircuit
import numpy as np
qc = QuantumCircuit(1)
qc.ry(np.pi/2, 0)      # θ=π/2 → P(1)=sin²(π/4)=0.5
qc.measure_all()

np.pi/2→0.5、np.pi→1.0、np.pi/4→約0.146、3*np.pi/4→約0.854 はそのまま覚える。

💡 なぜ角度が半分($\theta/2$)なのか + |+⟩|−⟩ 記法

数式では |0⟩ と |1⟩ は90°ズレた直交ベクトルだが、Bloch球ではこれを180°(真反対)に描く=角度を2倍に拡大した地図。だからBloch球で「$\theta$ 倒す」と、係数の世界では半分の $\theta/2$ で効く。式は暗記でなく「北極から $\theta$ 倒す→$\cos\frac\theta2|0\rangle+\sin\frac\theta2|1\rangle$」と図から書ける。赤道(真横)=半々=$P(1)=0.5$。

$|+\rangle=\frac{1}{\sqrt2}(|0\rangle+|1\rangle)$、$|-\rangle=\frac{1}{\sqrt2}(|0\rangle-|1\rangle)$ はHで作る重ね合わせの略記。計算で猛烈に便利:$H|0\rangle=|+\rangle$, $H|1\rangle=|-\rangle$, $H|+\rangle=|0\rangle$, $H|-\rangle=|1\rangle$。多段回路は $\frac{1}{\sqrt2}(\dots)$ を展開せず、この行き来で一発。Bloch球では $|+\rangle$=赤道+x、$|-\rangle$=赤道−x。

軸+方向−方向$|1\rangle$係数の特徴
Z軸$|0\rangle$$|1\rangle$重ね合わせでない

💡 主要ゲートの行列(行列を見て当てる問題の判定表)

行列からゲートを当てる問題は、「値がどこにあるか」と「特徴的な数」で判定できます。

$I=\begin{pmatrix}1&0\\0&1\end{pmatrix}\qquad X=\begin{pmatrix}0&1\\1&0\end{pmatrix}\qquad Y=\begin{pmatrix}0&-i\\i&0\end{pmatrix}$

$Z=\begin{pmatrix}1&0\\0&-1\end{pmatrix}\qquad H=\dfrac{1}{\sqrt2}\begin{pmatrix}1&1\\1&-1\end{pmatrix}=\begin{pmatrix}0.707&0.707\\0.707&-0.707\end{pmatrix}$

見た目の特徴ゲート
対角に 1, 1I
反対角に 1, 1(実数)X
反対角に $\pm i$(虚数 j)Y
対角に 1, −1Z
4つとも 0.707、右下だけ −H

とくに 0.707(= $1/\sqrt2$)が見えたら H のサインです(Hは重ね合わせを作るゲートなので $1/\sqrt2$ が現れます)。Z は 0.707 を含みません(1 と −1 だけ)。X と Y の区別は次のコラムの通り、虚数 $i$ の有無で行います。

⚠ 勘違い注意①:X と Y は行列がそっくり($i$で見分ける)

$X=\begin{pmatrix}0&1\\1&0\end{pmatrix}$、$Y=\begin{pmatrix}0&-i\\i&0\end{pmatrix}$。どちらも「反対角」で似ているが、虚数 $i$ があれば Y、実数1なら X。状態も同じで、$|1\rangle$係数が ±1なら X軸($|\pm\rangle$)、±$i$ なら Y軸($|\pm i\rangle$)。
Qiskit/Pythonの行列出力では虚数を j で書く:0.-1.j=$-i$、0.+1.j=$+i$。出力に ±1.j(虚部が0でない成分)があれば Y が含まれる。1.+0.j はただの1。

⚠ 勘違い注意②:「状態を動かさないゲート」は基準状態で逆になる

「位相ゲート(Z,S,T)は状態を変えない」は |0⟩・|1⟩ 限定のルール。$|+\rangle$/$|-\rangle$ に対しては逆で、Z系が状態を変え(例:$Z|+\rangle=|-\rangle$)、動かさないのは X と I。
原理:状態が乗っている軸のゲートは、その状態を動かさない。|0⟩→Z軸なのでZ系が無力、|+⟩→X軸なのでXが無力、$|+i\rangle$→Y軸なのでYが無力。$I$ は常にどの状態も動かさない。
「$|+\rangle$ を変えないゲートは?」→ X と I(Z・S・T ではない)。

💡 Involutory(対合)= $M^2=I$(2回で元に戻る)

「2回かけると単位行列に戻る」ゲート。X, Y, Z, H, I は involutory(自分が逆)。T・S は違う($T^2=S$, $S^2=Z$、位相を半端に回すので一周しない)。パウリとHがエルミートかつユニタリ→$M^2=I$、という①の性質と同じ話。

💡 ランダム生成関数は random_○○(スネークケース・対象を明示)

qi.random_unitary(dim) / random_statevector / random_density_matrix / random_pauli。RandomUnitary(大文字始まり=クラス風)や random(3)(対象なし)、unitary(3) はダミー。Qiskitの関数は小文字スネークケース＋対象を明示、が命名の見分け方。

1-4. Pauli クラスとテンソル積(超頻出)

Pauli('AB') は $A\otimes B$ を表す。Qiskitはリトルエンディアン:文字列の右端が qubit 0。

from qiskit.quantum_info import Pauli, SparsePauliOp
Pauli('IZ').to_matrix()   # I⊗Z = diag(1,-1,1,-1)  右端Zがq0
Pauli('-ZI').to_matrix()  # 先頭の符号は全体にかかる
# 観測量(オブザーバブル)は SparsePauliOp で表す
obs = SparsePauliOp(['ZZ','IX'], coeffs=[1.0, 0.5])

テンソル積 $A\otimes B=\begin{pmatrix}A_{11}B & A_{12}B\\A_{21}B & A_{22}B\end{pmatrix}$。$I\otimes Z=\mathrm{diag}(1,-1,1,-1)$、$Z\otimes Z=\mathrm{diag}(1,-1,-1,1)$。手計算できるように。

⚑ 試験ポイント
与えられた4×4行列から正しい Pauli('..') を選ぶ問題が出る。①右端=q0、②先頭の-は全体係数、を押さえれば解ける。
💡 行列 ↔ 基底状態 ↔ Dirac記法(ここが全部つながる)

行列の各成分の位置が基底状態に対応:成分(行 $i$, 列 $j$) = $|i\rangle\langle j|$(ケット=行、ブラ=列)。例:$M=\begin{pmatrix}2&-1\\-9&3\end{pmatrix}=2|0\rangle\langle0|-|0\rangle\langle1|-9|1\rangle\langle0|+3|1\rangle\langle1|$。ブラケットの順序を逆にした選択肢が定番のワナ。

対角成分=「その基底状態を測ったときの値(固有値)」。観測量が対角なら状態を変えず値だけ与える。$Z\otimes Z$ の対角 $(1,-1,-1,1)$ は「各qubitの $0\to+1,1\to-1$ の掛け算」。だから Bell では $\langle ZZ\rangle=1$。

行列の性質:ゲートは全てユニタリ($U^\dagger U=I$・可逆)、観測量はエルミート($M^\dagger=M$)。パウリ(X,Y,Z)とHは両方($M^2=I$)。対角行列なら「実数→エルミート」「絶対値1→ユニタリ」「0か1のみ→射影($M^2=M$)」で即判定。

1-5. 多量子ビットゲート

cx(ctrl,tgt)(CNOT)、cz、ccx(Toffoli)、swap、cp(λ)。制御ゲートは「制御が |1⟩ のときだけ標的にゲートを掛ける」。Bell状態は h(0) → cx(0,1) で $\frac{1}{\sqrt2}(|00\rangle+|11\rangle)$。

💡 引数の順序は全ゲート共通:角度 → 制御 → 標的

cx(0,1)=制御,標的 / ccx(0,1,2)=制御,制御,標的 / cp(λ,0,1)=角度,制御,標的 / crx(θ,0,1)=角度,制御,標的。CCXとCPが長いのは「制御が2つ」か「角度がある」かの違いだけで、並べ方は同じ。角度を持つゲートは必ず角度が先頭。x(1引数・無条件反転)と cx(2引数・条件付き反転)は別物——引数の数で見分ける。

💡 4つのBell状態(ヒストグラム・qsphere問題の土台)

$\phi$系=「00と11」、$\psi$系=「01と10」。$\pm$は位相。

$|\phi^+\rangle=\frac{1}{\sqrt2}(|00\rangle+|11\rangle)$ = h(0);cx(0,1)(素直)
$|\phi^-\rangle=\frac{1}{\sqrt2}(|00\rangle-|11\rangle)$ = h(0);z(0);cx(0,1)(qsphereの色が変わる)
$|\psi^+\rangle=\frac{1}{\sqrt2}(|01\rangle+|10\rangle)$ = h(0);x(1);cx(0,1)
$|\psi^-\rangle=\frac{1}{\sqrt2}(|01\rangle-|10\rangle)$ = h(0);x(1);z(0);cx(0,1)

💡 CX と CZ の動作と回路記号

CX(CNOT)=制御が1のとき標的を反転(X)。制御と標的の役割が違う(入れ替えると別物)→ 非対称、記号は ●と⊕。
CZ=制御が1のとき標的にZ(位相反転)。結局「両方が1のとき位相を−1倍」で、これは制御・標的を入れ替えても同じ(ANDは対称)→ 対称、記号は ●と●。
⊕(プラスの丸)があれば反転する系(CX/CCX)、●だけなら CZ。CZは状態を動かさず位相だけ変えるので確率は不変(qsphereでは |11⟩ だけ色が変わる、ヒストグラムでは変化なし)。
回路記号まとめ:×と×=SWAP / ●と⊕=CX / ●●と⊕=CCX(Toffoli) / ●と●=CZ。

3-4. ダイナミック回路(Dynamic circuits・v2の目玉)

測定結果に応じて実行時にゲートを変える「古典制御フロー」。with 構文を使う。

qc.measure(q0, c0)
with qc.if_test((c0, 1)) as else_:   # c0==1 のとき
    qc.h(q1)
with else_:                          # それ以外
    qc.x(q1)

with qc.for_loop(range(3)):          # ループ
    qc.x(0)
with qc.while_loop((c0, 0)):         # 条件ループ
    qc.h(0); qc.measure(q0, c0)
with qc.switch(c0) as case:          # 多分岐
    with case(0): qc.x(0)
    with case(case.DEFAULT): qc.z(0)
⚠ 注意
古い .c_if() は非推奨。v2では if_test 系を使う。条件は (classical_bit, value) のタプル。
💡 条件は「二重カッコ」のタプル + 図の 0x 表記

正しい形は if_test((c0, 1))=二重カッコ。外側=メソッドの引数、内側=(ビット,値)のタプル。ワナ:if_test(c0, 1)(カッコ1組=別々の2引数)や if_test(c0==1)(比較式)は誤り。
回路図の c_0=0x1 は16進表記(0x1=1、0x0=0)。図問題は「else有無・if内のゲート・条件値(0x?)」の3点をコードと照合。レジスタ全体を条件にすると値が大きくなる(2ビットで11=0x3)。

3-5. 回路の合成

qc.compose(other)(他回路を連結)、qc.append(gate, qubits)、gate = sub.to_gate() / to_instruction() でサブルーチン化。ライブラリ:from qiskit.circuit.library import QFT, EfficientSU2 など。

⚠ 勘違い注意:回路連結は compose と &(add ではない)

2つの回路をつなぐ方法は2つ:メソッド qc0.compose(qc1) と 演算子 qc0 & qc1(&はcomposeのショートカット、同じ結果)。「複数選択で2つ選べ」だと compose と & の両方が答えになりやすい。

3-6. Bell状態の作り分け(頻出・作る/選ぶ両方で出る)

Bell状態の条件:制御=重ね合わせ(H)、標的=確定(0か1)、そして CX。CXは「制御が1のとき標的を反転」(標的の値ではなく制御が反転を決める)。標的の初期値で、できるペアが変わる。

作りたい状態コードペアの特徴
$\frac{1}{\sqrt2}(|00\rangle+|11\rangle)$h(0); cx(0,1)同じ値(00と11)
$\frac{1}{\sqrt2}(|00\rangle-|11\rangle)$h(0); z(0); cx(0,1)同じ値・位相−
$\frac{1}{\sqrt2}(|01\rangle+|10\rangle)$h(0); x(1); cx(0,1)違う値(01と10)→ x(1)を足す
⚠ 勘違い注意:「00と11」か「01と10」かで x(1) の要否が変わる

目標が同じ値のペア(00/11)→ 標的は|0⟩のまま(h(0);cx(0,1))。違う値のペア(01/10)→ 標的を|1⟩に(x(1) を追加)。
不正解の典型:①制御を x(0) で確定にしてしまう(重ね合わせでない→もつれない)、②標的に h(1) で重ね合わせにする(標的は確定であるべき)、③cx でなく cz を使う。迷ったらCXの動作(制御1→標的反転)で1ステップずつ追う。

3-7. initialize と Operator の作り方

⚠ 勘違い注意:initialize の対象qubit指定

qc.initialize(vec)(省略=全qubit)または qc.initialize(vec, [0,1])(リストで明示)。initialize(vec, all) はエラー(all はPython組み込み関数で使えない)。もつれ状態は2qubitまとめた4要素ベクトルで初期化する(v0,v1に分けて個別 initialize すると積状態にしかならず、もつれは作れない)。ベクトルの中身が目標の状態と一致するかも必ず確認($[0,0.707,0.707,0]$=01/10、$[0.707,0,0,0.707]$=00/11)。

Operator(qc)(回路から)または Operator([[1,0],[0,-1]])(2×2行列から)。Operator.define(...) は存在しないメソッド。行列は必ず [[行],[行]] の形([[1,0,-1,0]] は1×4で形が違い、Zにならない)。

3-8. QuantumCircuit の主なメソッド・属性(リファレンス)

ここは辞書的に眺めておくだけで十分です。すべてを暗記する必要はありません。命名には一貫した規則があるので、規則を掴んでおけば初めて見る名前でも判断できます。

用途名前
個数を知るnum_qubits / num_clbits / num_ancillas / num_parameters
中身を取り出すqubits / clbits / ancillas / qregs / cregs / parameters / data(命令列)/ layout(変換後の配置)
制御フローを書くfor_loop() / while_loop() / break_loop() / continue_loop() / if_test()

💡 名前の規則(3つ)

① 個数は num_ + 対象。対象は種類ごとに分かれており(qubits / clbits / ancillas)、すべてを合算した名前は用意されていません。
② ループ関係はすべて _loop で終わります(for_loop, while_loop, break_loop, continue_loop)。1つ分かれば残りも同じ形だと分かります。
③ 操作は「動詞_対象」(add_bits, get_parameter, assign_parameters)。動詞がない単独の名前は、たいてい属性かダミーです。

💡 制御付きゲートの作り方

.control() は「そのゲートに制御を1つ追加する」メソッドです。したがって:

・XGate().control() → X に制御が1つ付いて CX(CNOT)
・ZGate().control() → CZ
・XGate().control(2) → 制御が2つで CCX(Toffoli)

注意したいのは、すでに制御が付いているゲートに .control() を足すと、さらに制御が増えることです。CX が欲しいときに CXGate().control() とすると、制御が2つの CCX になってしまいます。素のゲートから始めるのが基本です。

💡 n qubit の行列の大きさ

n qubit の状態は $2^n$ 通りあるので、状態ベクトルは $2^n$ 個の要素を持ちます。そこに作用する演算子(ゲート)は$2^n \times 2^n$ の正方行列です。1 qubit なら 2×2、2 qubit なら 4×4、3 qubit なら 8×8。2の n 乗であって、2×n ではないことに注意してください。

coupling_map で直結していない2qubit間にCXを掛けると、トランスパイラがSWAPゲートを自動挿入して物理的に隣接させる。「0と2が直結なし+CX」→ SWAPが入った回路図を選ぶ。initial_layout の対応(論理→物理)も図で確認する問題が出る。

実機を使う場合:pm = generate_preset_pass_manager(optimization_level=1, backend=backend) と backend を渡す。

⚠ 勘違い注意:図から optimization_level を逆算する

「どのコードでこの回路図になる?」型では、図に無駄なゲートが残っているかで level を判定:
・無駄な連続ゲート(例:H が2連続=$H\cdot H=I$)が残っている → optimization_level=0(最適化なし)
・無駄なゲートが消えて整理されている → optimization_level=1〜3(最適化あり。連続Hは削除される)
initial_layout は図の「q0↦物理?, q1↦物理?」から読む(例:q0→物理1, q1→物理0 なら [1,0])。

⚠ 勘違い注意:H で挟まれた CX は「向き反転」

coupling_map は接続だけでなくCXの向きも制約することがある(例:0→1の向きしか使えない)。逆向き(1→0)のCXが必要なとき、両qubitをHで挟むと制御と標的が入れ替わる:$\text{CX}(1{\to}0)=(H\otimes H)\,\text{CX}(0{\to}1)\,(H\otimes H)$。
回路図で「余分なHに挟まれたCX(H–CX–H)」を見たら向き反転と読む。SWAP挿入(=直結していないqubit間)とは別物(こちらは向きが逆なだけ)。

5-0. そもそも Primitive とは何か

量子コンピュータに計算をさせて、私たちが最終的に知りたいことは、突き詰めると2種類しかありません。

  • 「どの状態が、どれくらいの確率で出るのか」を知りたい — 例:組合せ最適化で「良い答えの候補」を集めたいとき。→ Sampler
  • 「ある物理量の平均値はいくつか」を知りたい — 例:分子のエネルギーを求めたいとき。→ Estimator

この2つを標準的な道具として用意したものが Primitive(プリミティブ=基本要素) です。「量子計算のやりたいことは、結局この2つに集約できる」という設計思想から、この名前が付いています。

5-1. Sampler は「分布を見る」道具

Sampler は回路を何度も繰り返し実行し、測定結果を集計して、どのビット列が何回出たかを返します。サイコロを何百回も振って出目を数えるイメージです。

from qiskit_ibm_runtime import SamplerV2 as Sampler
sampler = Sampler(mode=backend)          # 実行の場を渡す(§0参照)
sampler.options.default_shots = 300      # 「回路を何回実行するか」
job = sampler.run([isa_circuit])         # PUB のリストを渡す
result = job.result()
counts = result[0].data.meas.get_counts()
💡 なぜ Sampler には measure が必要なのか

Sampler が返すのは「測定した結果の集計」です。つまり測定していないものは集計できません。だから回路に measure が入っていなければ、Sampler は何も数えられず意味のある結果になりません。

逆に言えば、「measure が必要かどうか」は暗記ではなく、返すものが測定結果の集計だから当然必要、と理解できます。

💡 shots(ショット数)の意味

量子測定は本質的に確率的なので、1回実行しただけでは分布は分かりません。同じ回路を何度も実行して、はじめて「どの状態が何割出るか」が見えてきます。この繰り返し回数が shots です。

shots を増やすほど分布の精度は上がりますが、その分だけ実行時間もかかります。default_shots は「回路を実行する回数」を指す、という理解で正確です。

5-2. Sampler と Estimator の違い(ここを理解すれば⑤⑥は解ける)

6-1. Estimator は「平均値を求める」道具

Estimator は、回路が作った状態に対してある物理量の平均値(期待値)を返します。返ってくるのは分布ではなく、1つの数値です。

from qiskit_ibm_runtime import EstimatorV2 as Estimator
from qiskit.quantum_info import SparsePauliOp

obs = SparsePauliOp("ZZ")                # 測りたい物理量(オブザーバブル)
estimator = Estimator(mode=backend)
job = estimator.run([(isa_circuit, obs)])
evs = job.result()[0].data.evs           # 期待値。誤差は .stds
💡 オブザーバブル(observable)とは何か

オブザーバブルは「何を測りたいか」を指定するものです。日本語では「観測量」と訳されます。

たとえば同じ量子状態でも、「Z方向の値を知りたい」のか「X方向の値を知りたいのか」で、測るべき量は変わります。SparsePauliOp("ZZ") は「2つの qubit の Z を掛け合わせた量」を意味します。回路が「どんな状態を作るか」を決め、オブザーバブルが「その状態の何を測るか」を決める、という役割分担です。

💡 なぜ Estimator には measure が要らないのか

Sampler では自分で measure を書きました。しかし Estimator では書きません。理由は、「何をどう測るか」をオブザーバブルとして既に渡しているからです。

Estimator は、渡されたオブザーバブルに応じて必要な測定を内部で自動的に組み立てて実行します。私たちが手で measure を書くと、むしろその仕組みと衝突してしまいます。

つまり:Sampler は「測って数える」ので measure が要る。Estimator は「何を測るか」を observable で伝えるので measure は要らない。これは暗記ではなく、役割の違いから自然に導けます。

💡 期待値(expectation value)とは

期待値は「何度も測ったときの平均値」です。量子測定は1回ごとに結果がばらつくので、たくさん測って平均を取ります。その平均が期待値で、結果の data.evs(expectation values)に入ります。

平均には必ずばらつき(誤差)が伴うので、Estimator は data.stds(standard deviations=標準偏差)も返します。「値」と「その誤差」がセットで返ってくる、と理解してください。

6-2. PUB — プリミティブに渡す「1件の計算依頼」

PUB(Primitive Unified Bloc) は、「この回路で、これを、この条件で計算してください」という依頼1件分のまとまりです。run() にはこの依頼をリストで渡します(複数件まとめて頼めます)。

PUB の中身意味
Sampler(circuit, parameters, shots)この回路を、この値を入れて、何回実行するか
Estimator(circuit, observable, parameters, precision)この回路の、この物理量を、この値を入れて、どの精度で求めるか
💡 PUB に入るもの・入らないものの区別

PUB に入るのは「計算の内容」だけです。「どこで・どう実行するかという設定」は入りません。

・計算内容(PUBに入る):回路、オブザーバブル、パラメータ値、精度
・実行の設定(PUBに入らない):バックエンド(プリミティブ作成時の mode= で指定)、誤り緩和の強さ(options で指定)

「何を計算するか」と「どう実行するか」は別のレイヤーだ、と考えると自然に切り分けられます。

💡 パラメータ回路 — 値を後から差し込める回路

PUB の parameters は「パラメータ回路の空欄に入れる値」です。

通常の回路は qc.ry(0.5, 0) のように角度が固定されています。これに対し theta = Parameter('θ') として qc.ry(theta, 0) と書くと、角度を空欄にしたまま回路の形だけを組めるようになります。料理のレシピで「塩を X g」と書いておくようなものです。

これが効くのは VQE や QAOA のように、角度を少しずつ変えながら何十回・何百回と試して最適な値を探すアルゴリズムです。毎回回路を組み直す代わりに、同じ回路に値だけを差し替えて実行できます。

6-3. precision と shots の関係(計算問題)

必要ショット数は精度の2乗に反比例:$\text{shots}\propto 1/\text{precision}^2$。precisionの値を大きくする(=精度を粗くする)とショット数は減る。例:0.015625→0.03125(2倍粗く)で、ショットは約 $1/4$ に減少。ワナ:precisionは「許容誤差」なので値が大きい=精度が低い(逆)。結果の data.stds(標準偏差=誤差)は precision を小さくする(shots増)ほど小さくなる。

💡 3つの言葉を、意味から区別する

誤りへの対処には3つのレベルがあり、英単語の意味がそのまま違いを表しています。

・error suppression(抑制) — suppress は「抑え込む」。実行している最中に、ノイズが乗るのを予防します。
・error mitigation(緩和) — mitigate は「和らげる」。実行が終わった後に、結果を計算で補正します。
・error correction(訂正) — correct は「訂正する」。誤りを検出して直接修正する最も高度な方法で、現在のプリミティブでは提供されていません。

したがって「誤り訂正がデフォルトで有効になっている」という趣旨の選択肢は誤りです。予防(実行中)→ 補正(実行後)→ 訂正(未提供)という段階で捉えてください。

💡 DD と Twirling — 何をしているかで区別する

どちらも抑制(実行中の予防)ですが、アプローチが全く違います。

DD(Dynamical Decoupling)は「パルスで守る」
qubit は放っておくと周囲の環境の影響で状態が崩れていきます。そこで短いパルスを一定の間隔で繰り返しかけ続けることで、環境からの影響を打ち消し、状態をより長く保ちます。decoupling(切り離す)という名前は、qubit を環境ノイズから切り離すことを表しています。

Twirling は「ランダム化してならす」
実機のノイズには「いつも同じ方向に偏る」性質(系統誤差)があります。そこで回路にランダムな変化を加えて何度も実行し、偏りを平均化して打ち消します。twirl(ひねる・回す)という名前は、このランダムな変換を表しています。

整理すると、DD = パルスで状態を保つ / Twirling = ランダム化して誤差を平均化する。この2つは説明が入れ替えて出題されやすいので、「パルス」と「ランダム化」という語で区別してください。

💡 緩和の3手法と、resilience との関係

resilience は「回復力・耐性」という意味で、誤り緩和(mitigation)の設定を指します。ここに入るのは緩和の手法だけです。

・ZNE(Zero Noise Extrapolation)— わざとノイズを増やして何度か測り、その傾向から「ノイズが0だったらどうなるか」を外挿して推定します。
・TREX(Twirled Readout Error eXtinction)— 測定そのものの読み取り誤りを学習して取り除きます。
・PEC(Probabilistic Error Cancellation)— ノイズの逆の操作を確率的に混ぜて誤りを相殺します。最も精度が高い一方、コストも最大です。

一方 DD と Twirling は抑制なので resilience には含まれず、それぞれ別の設定項目になります。

💡 どちらのプリミティブで使えるのか

・抑制(DD / Twirling)は Sampler でも Estimator でも使えます。実行中にノイズを防ぐ工夫なので、何を返す道具かに関係なく有効だからです。
・緩和(ZNE / TREX / PEC)は Estimator が中心です。これらは期待値という「数値」を補正する技術なので、期待値を返す Estimator と結びついています。

6-5. ブロードキャスト(4パターン・図問題対応)

1つのPUBで「複数のパラメータ集合 × 複数のオブザーバブル」をまとめて渡すとき、その組み合わせ方(ブロードキャストのルール)が4種類ある。図で (3,6) のような shape(形) が示され、「どのパターンか」を問われる。まず全体像:

💡 shape から判定する手順(NumPyルール)

2つの形を右端(末尾)から揃えて比較する。各次元で:
・数が同じ → そのまま
・片方が1 → もう片方の数に拡張
・どちらも1でなく違う → エラー(組めない)
例:(3,6) と (2,3,1) → 右揃えで (1,3,6) と (2,3,1) → 末尾 6と1→6、中央 3と3→3、先頭 1と2→2 → 結果 (2,3,6)。これが standard nd generalization。

・観測量が1個だけを配る → broadcast single observable
・両者同じ形で1対1 → zip(結果の要素数も同じ)
・全組み合わせ(直積)で要素が増える → outer/product
・形が違い、1の次元が拡張されて結果shapeになる → standard nd generalization(今回の頻出図)
図で示された「入力shape → 結果shape」を見て、1の次元が相手の数に化けていたら standard nd generalization。

job.job_id(); job.status()         # 例: 'DONE','QUEUED'...
result = job.result()              # PrimitiveResult
pub_res = result[0]                # PubResult(PUBごと)
data = pub_res.data                # DataBin
# Sampler: data.<creg>.get_counts() / .get_bitstrings()
# Estimator: data.evs(期待値), data.stds(標準偏差)
💡 結果は「入れ子」になっている

結果の取り出しが長く見えるのは、階層をたどっているだけだからです。

job(実行の依頼票)→ .result() → 結果全体(依頼が複数あるのでリスト)→ [0] → 1件目の結果 → .data → データ本体 → 中身(Sampler ならレジスタ名、Estimator なら evs)

つまり job.result()[0].data.c.get_counts() は、「ジョブの結果の、1件目の、データの、c レジスタの、集計」と読めます。丸暗記ではなく、外側から内側へ順にたどっていると理解してください。

7-1b. ジョブの状態を調べるメソッド

ジョブは投入してすぐに終わるとは限らないため、状態を確認する手段が用意されています。名前はやりたいことを素直な英語にしたものです。

やりたいことメソッド返るもの
今の状態を知るstatus()文字列('QUEUED' 'RUNNING' 'DONE' など)
実行中かどうかrunning()True / False
正常に終わったかdone()True / False
もう変化しない状態かin_final_state()True / False
終わるまで待つwait_for_final_state()(完了まで待機する)
失敗の理由を見るerror_message()エラーメッセージ
ジョブIDを得るjob_id()ID文字列
💡 名前の考え方(2つだけ意識すれば十分)

・状態を尋ねるものは、状態を表す形になります。「実行する」は run() ですが、「実行中ですか?」は running() です。動作と状態は別物、という区別だけ持っておいてください。
・最終状態(final state)とは、DONE・ERROR・CANCELLED のようにもうそれ以上変化しない状態のことです。「今そうなっているか」を尋ねるのが in_final_state()、「そうなるまで待つ」のが wait_for_final_state() です。

過去のジョブを取り出したいときは service.job(job_id)(1件)/ service.jobs()(一覧)、バックエンドは service.backend("名前")(1件)/ service.backends()(一覧)を使います。単数形が1件、複数形が一覧という素直な対応です。

7-2. 測定結果の取り出し方:.data.c と .data.meas

Samplerの結果は「result[0].data.レジスタ名.get_counts()」で取る。このレジスタ名が、測定コードによって変わるのが最大の罠。

測定コード作られる古典レジスタ名結果取得
QuantumCircuit(2, 2) + measure([0,1],[0,1])c(既定名)data.c.get_counts()
ClassicalRegister(2,"myc") を使う付けた名前 mycdata.myc.get_counts()
measure_all()meas(自動)data.meas.get_counts()
⚠ 勘違い注意:コードの追加問題は「取得側の名前」と合わせる
「既存コードに測定を追加せよ」型の問題は、下の方にある取得コードが .data.c か .data.meas かを見て決める。.data.c なら measure([0,1],[0,1])、.data.meas なら measure_all()。逆にすると名前が合わずエラー。measure_all() が作る名前は必ず meas。
なお Measure(...)/Measure_all()(大文字始まり)や引数なしの measure() はすべて実行エラー=消去できる。

7-3. カウント辞書から値を取り出す

get_counts() が返すのはただのPython辞書(例 {'00':512,'11':512})。だから値の取り出しはPython標準の方法:

counts = job.result()[0].data.c.get_counts()
counts.get('00')     # 512(get メソッド。無いキーは None)
counts['00']         # 512(角カッコ。無いキーは KeyError)
💡 ここは Qiskit ではなく Python の知識で解ける

get_counts() が返すのはごく普通の Python 辞書です。したがって特定のビット列の回数を知りたければ、Python の通常の書き方 .get('00') または ['00'] を使います。

コード中に result() が何度も出てくるため引きずられやすいのですが、result() はジョブに対して使うもので、辞書に対しては使いません。今どの型のものを触っているのかを意識すると迷いません。

7-4. BitArray の扱い

SamplerV2の測定結果は BitArray。.get_counts()(辞書)、.get_bitstrings()(1ショットずつのリスト)、.array(NumPy配列)、.num_shots などを持つ。

💡 略語の意味(覚えやすくなる)

creg=classical register、qreg=quantum register。evs=expectation values(期待値)、stds=standard deviations(標準偏差=誤差)。末尾のsは「複数返りうる」から複数形。Estimator結果は「値(evs)+誤差(stds)」のペア。mpl=matplotlib(qc.draw("mpl")。他に "text"/"latex")。Pythonでは虚数を j と書く=数学の i。0.-1.j は −i、1.+0.j はただの1(+0.j は飾り)。

7-5. セッションの情報を見る

セッションには、情報を取り出すメソッドが3つあります。返ってくるものが違うので、目的に応じて使い分けます。

メソッド返るもの使う場面
session.details()セッション情報の辞書詳細をまとめて見たいとき
session.status()状態の文字列今開いているか等を知りたいとき
session.usage()使用時間の数値(秒)どれだけ使ったか知りたいとき
💡 details に入っているのは「セッション自身の情報」だけ

details() の辞書には、そのセッションについての情報が入っています。大きく4種類です。

・身元:id / backend_name / mode
・状態:state / accepting_jobs(新しいジョブを受け付けるか)
・時刻:started_at / closed_at / activated_at / last_job_started / last_job_completed
・時間:usage_time / max_time / interactive_timeout / active_timeout

逆に言えば、セッション自身のことではないもの——たとえば実行した回路の中身や、誤り緩和の設定、量子デバイス側の状態——は含まれません。「これはセッション自身の情報か?」という基準で判断できます。

💡 セッションの閉じ方は2種類ある

どちらもセッションを終了しますが、実行中のジョブの扱いが逆です。

・close() — 新しい受付は止めるが、すでに投入済みのジョブは最後まで実行させます。お店の「閉店作業」に近く、中のお客さんは対応し終えてから閉めるイメージです。
・cancel() — 実行中・待機中のジョブごと打ち切ります。

「ジョブを完了させたい」なら close()、「今すぐ止めたい」なら cancel()。目的で選び分けてください。

8-3. QASMプログラムの構文ルール(loads で読む問題)

QASM文字列を qasm3.loads(program) で読み込む問題では、program 文字列の書式が正しいものを選ぶ。

⚠ 勘違い注意:3つの必須ルール

① 1行目は正確に OPENQASM 3.0;(OPENQASM=OPEN+QASM、全部大文字1語)。QASM 3.0;(OPEN欠落)はエラー。
② OPENQASM 3.0; は必ず最初の行(includeや宣言より前)。位置がずれた選択肢はエラー。
③ 使う変数(bit/qubit)は使う前に宣言する。meas[0] = measure q[0]; があるのに bit[1] meas; が無ければ未宣言エラー。
正しい順序:OPENQASM 3.0; → include → bit/qubit 宣言 → 操作。Qiskitの「測定結果は古典ビットに格納」がQASMでは「bit を宣言してから measure」に対応。QASM問題は毎回違う箇所(綴り/位置/宣言漏れ)を突くので全項目チェック。

OPENQASM 3.0;                # ① 必ず先頭
include "stdgates.inc";
bit[1] meas;                 # ② 使う古典ビットを宣言
qubit[1] q;
h q[0];
meas[0] = measure q[0];

実行フロー(並び替え問題はこれ)

  • service → backend → 回路 → transpile(ISA) → primitive → run → result
  • 判断基準:使う変数は、使う前に作られている
  • プリミティブ=mode=(実行の場) / Session・Batch=backend=(実機)
  • プリミティブに渡すのは変換済み(ISA)回路

位相(対|1⟩)

  • T → π/4
  • S → π/2
  • Z → π
  • Tdg/Sdg → 負符号
  • P(λ) → λ

Pauli / 状態の順序

  • Pauli('AB')=A⊗B
  • 右端 = qubit 0
  • 先頭の-は全体係数
  • Statevector index $k$=2進 $q_{n-1}..q_0$

RY確率

  • $P(1)=\sin^2(\theta/2)$
  • π/2→0.5, π→1.0
  • π/4→0.146, 3π/4→0.854

qsphere

  • 色=位相(同色=同位相)
  • 大きさ=確率
  • z(0)足すと色変化

レジスタ

  • 測定結果→Classical
  • 量子→Quantum、補助→Ancilla
  • Circuit registerは無い

実行モード

  • single job / batch / session
  • batch=順序保証なし
  • session=専有・呼出をグループ化

トランスパイル

  • generate_preset_pass_manager
  • opt_level 0〜3
  • 非直結+CX→SWAP挿入
  • ISA回路=装置に適合

Sampler

  • 分布を返す/measure必要
  • run([pub])
  • shots=実行回数
  • 結果 data.meas.get_counts()

Estimator

  • 期待値/measure不要
  • PUB=(circ, obs, params, precision)
  • precision↑→shots↓→精度↓
  • 結果 data.evs

誤り対策

  • DD=パルスで状態を保つ / Twirling=回路をランダム化(両方=抑制)
  • 抑制:DD, Twirling(Sampler/Estimator両方)
  • 緩和=resilience:ZNE, PEC, TREX(Estimatorのみ)
  • resilienceにDD/Twirlingは入らない
  • correction(訂正)は未提供=「デフォルト有効」は誤り

session.details() 入る

  • 身元:id / backend_name / mode
  • 状態:state / accepting_jobs
  • 時刻:started_at / closed_at / activated_at / last_job_started / last_job_completed
  • 時間:usage_time / max_time / interactive_timeout / active_timeout

結果の取り出し

  • measure([0,1],[0,1])→.data.c
  • measure_all()→.data.meas
  • 回数:get_counts().get('00')
  • プリミティブ=mode= / Session・Batch=backend=
  • 閉じる:close()=ジョブ完了 / cancel()=中断

覚えるしかない引数名

  • 実機:simulator=False
  • 接続保存:token=
  • 時間上限:max_time=
  • 結合:coupling_map=[[0,1],..]

ジョブ状態メソッド

  • 状態:status()
  • 実行中:running()
  • 完了:done()
  • 最終状態か:in_final_state()
  • 終わるまで待つ:wait_for_final_state()
  • エラー:error_message()

名前の規則

  • 個数=num_+対象
  • ループ=全部_loop
  • 操作=動詞_対象(add_bits等)
  • 単数=1件 / 複数形=一覧
  • n qubit → 2ⁿ×2ⁿ 行列

状態と軸(見分け)

  • Z軸:|0⟩|1⟩ / X軸:|±⟩ / Y軸:|±i⟩
  • 係数±1=X軸、±i=Y軸
  • 乗る軸のゲートが動かさない
  • 虚数(j)あり→Y

Hの個数

  • H 1個→2状態(0.707×2)
  • H 2個→4状態(0.5×4)
  • Xは広げない(確定反転)
  • h(reg)=全qubit / h(reg[i])=1個

回路連結 / involutory

  • 連結:compose と &(addは×)
  • involutory($M^2=I$):X,Y,Z,H,I
  • T,S は違う($T^2=S$)

OpenQASM 3

  • 型:int/uint/float/bool/bit/complex/angle/duration
  • ✗ class/char/enum/string
  • ファイル=dump/文字列=dumps/読込=load/loads
  • program は OPENQASM 3.0; 先頭＋変数宣言
